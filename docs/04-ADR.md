# Architectural Decision Records (ADR) — IntentMarket

## ADR-001: Выбор Supabase вместо собственной инфраструктуры
* **Статус:** Принято.
* **Контекст:** Необходим быстрый запуск MVP с PostgreSQL, геопоиском (PostGIS), векторным поиском (pgvector), авторизацией и файловым хранилищем.
* **Решение:** Использовать Supabase как единую backend-платформу.
* **Последствия:** Экономия времени разработки (нет необходимости писать и поддерживать серверные CRUD/Auth API с нуля), бесплатный старт, соответствие требованиям безопасности через RLS.

## ADR-002: Разделение таблиц `listings` и `external_listings`
* **Статус:** Принято.
* **Контекст:** Агрегированные предложения из открытых источников имеют другой жизненный цикл, юридический статус и набор полей, чем объявления собственных пользователей.
* **Решение:** Хранить внешние объявления в отдельной таблице `external_listings` с полями провенанса (`source_id`, `external_id`, `retrieved_at`, `availability_status`), не смешивая с `listings`.
* **Последствия:** Чистота базы пользователей, защита от случайной модификации, прозрачная аналитика конверсии внешних предложений во внутренние.

## ADR-003: Двухкнопочный интерфейс («Ищу» vs «Предлагаю»)
* **Статус:** Принято.
* **Контекст:** Одно абстрактное поле поиска создает путаницу для пользователей и заставляет нейросеть угадывать тип намерения на неполных фразах (*«iPhone 15 25000 Одесса»*).
* **Решение:** Два выразительных таба/кнопки на главном экране.
* **Последствия:** 100% точность определения типа намерения (`DEMAND` vs `SUPPLY`) до обращения к AI, адаптированные подсказки и действия под каждый сценарий.

## ADR-004: Модель монетизации без комиссии (0% Commission + AdMob)
* **Статус:** Принято.
* **Контекст:** На старте любая комиссия с транзакций отпугивает пользователей и продавцов.
* **Решение:** 100% бесплатные прямые звонки для внутренних объявлений. Монетизация через Google AdMob (нативные карточки в ленте + показ спонсорского блока при переходе к внешним источникам).
* **Последствия:** Максимальный органический приток пользователей, отсутствие юридических сложностей с эквайрингом и escrow на первом этапе.
